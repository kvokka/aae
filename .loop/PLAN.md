# План aae

> **Сначала прочитай `.loop/OWNER-RULES.md`** (правила владельца для coder и reviewer: CI не ждём, эксперт и beads).

Порядок — по §16: каркас → опыты → контракты → ядро → фронтенды и демон → адаптеры → плагины → поставка и
приёмка. Фронтенды (HTTP API, CLI) идут раньше адаптеров харнессов: acceptance spec гоняет настоящий демон, и
сценарии на exec-шагах и сценарном харнессе должны появиться как можно раньше.

Размеры: S ≈ до 60k рабочего контекста кодера, M ≈ до 150k. L нет. За цикл — один M или два S. Статусы:
todo | doing | done | blocked | split (разбит, работа — в дочерних пакетах). Пакеты с пометкой «критичный» начинаются с плана expert (или, если expert
недоступен, с письменного плана кодера в `.loop/cycles/NN/notes/`) до кода.

Раскладка кода (крейт создаётся пакетом, который его первым наполняет; пустых крейтов нет):

| Путь | Строка бюджета §14 |
|---|---|
| `crates/aae-core` | ядро ≤ 12 000; не зависит ни от одного другого крейта aae |
| `crates/aae-claude`, `crates/aae-codex` | адаптер харнесса ≤ 3 500 каждый |
| `crates/aae-br` | адаптер трекера ≤ 1 200 |
| `crates/aae-front` (модули `http`, `cli`, `mcp`) | три фронтенда ≤ 4 000 |
| `crates/aae-plugins` (`default_policy`, `worktree`) | плагины в комплекте ≤ 1 500 |
| `crates/aae` (bin: сборка, `doctor`, файлы сервиса, паки, мост MCP) | запас ≤ 4 300 |
| `crates/aae-testkit`, `crates/aae-acceptance`, `**/tests/`, `**/tests.rs` | тесты, вне бюджета |
| `**/generated/` | сгенерированный код, вне бюджета |
| `experiments/` | опыты §16, вне workspace и бюджета, ≤ 5 000 строк суммарно (владелец, 2026-11-14) |

Соглашение: юнит-тесты — в отдельных файлах `tests.rs` (`#[cfg(test)] mod tests;`), не внутри продуктового
файла, иначе счётчик строк засчитает их в бюджет.

Файл готовности §14 — `docs/READINESS.md`; обновляется в конце каждого пакета.

Опыты WP-02…WP-07 независимы друг от друга: кодер ведёт их параллельно через `subcoder` (до трёх), чтобы вся
фаза заняла 2–3 цикла.
