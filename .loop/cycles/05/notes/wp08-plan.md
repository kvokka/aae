# WP-08 — письменный план (expert недоступен, план кодера)

Документ: `docs/design/contracts.md`, английский, без пересказа опытов — ссылки на `docs/design/experiments.md`.

Разделы и ключевые решения:
1. Конверт события v1: `schema, seq, ts, type, project, rig, run, correlation, data`. Правила версии: добавление
   опционального поля/нового типа — без смены версии; удаление/переименование/смена смысла — `schema+1`.
   Потребители игнорируют незнакомое. Один конверт для журнала, SSE и stdin exec-хуков. `data` каждого типа §5.4.
2. Вид события для фильтров/шаблонов: поля конверта + поля `data` на одном уровне (ключи `data` не совпадают с
   полями конверта). `where`: ключ — путь через точку; значение — скаляр (равенство; для массива — «содержит»)
   или массив скаляров (любой из). Все ключи — И. Путь проверяется по схеме типа при загрузке конфига.
   `inputs` и шаблон промпта — один язык подстановки `{{path}}`; единственный плейсхолдер сохраняет тип JSON.
   Неразрешённый путь в inputs — `trigger.skipped{reason: input_unresolved}`.
3. Решения хуков: JSON-схема на каждое из пяти решающих событий; коды 0/2/прочее; композиция нескольких плагинов.
4. Таймауты хуков: 30 с по умолчанию, потолок 300 с, kill группы.
5. Outbox: запись живёт до подтверждения всеми постоянными потребителями (журнал, триггеры, диспетчер хуков);
   временного истечения нет — нет потери; возраст старейшей записи виден в статусе демона.
6. Интерфейс драйвера: операции §7.1 + `prompt.acked` (нужен журналу intent→sent→acked→settled §5.6);
   «хвост транскрипта» = статус доставки по ключу. Способности. Таблица соответствия сигналов claude/codex.
7. Интерфейс трекера: 12 операций, типы, ошибки; условность возврата/закрытия — сверка в адаптере.
8. Машина состояний прогона: таблица переходов, дедлайны каждого переходного состояния, потолки ядра.
   Решение [Д]: `interrupted` обобщается — «попытка закончилась сбоем, ждём решения `run.attempt_failed`»
   (рестарт демона — один из источников). Запись в журнал.
9. Ворота выдачи: ключи, запись, кто закрывает; полуоткрытой пробы в ядре нет (решение).
10. Реестр экземпляров: отпечаток, запись, жизненный цикл.
11. Сценарный харнесс в настоящем демоне: путь к бинарнику из конфига; в продукте тестового кода нет.

READINESS → 2: цикл событий, прогоны, триггеры, ворота, восстановление, реестр, адаптеры claude/codex/br,
exec-хуки, default-policy (таблица реакций в терминах решений). Фронтенды, worktree, общий MCP, сборка конфига — нет.
