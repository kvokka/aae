# WP-09 — письменный план (кодер)

Крейт `crates/aae-core` (первый наполнитель). Зависимости: rusqlite (bundled), tokio (rt, sync, time, macros),
serde, serde_json. Ядро не знает ни харнессов, ни br.

Механизмы и модули:
1. `clock.rs` — `Clock`: стенное время = база + прошедшее по `tokio::time::Instant`. Под `tokio::time::pause()`
   это и есть управляемые часы: тест двигает время `advance`, ожидание `sleep_until` просыпается ровно в срок.
   Собственных часов и интервала опроса нет.
2. `store.rs` — SQLite WAL, `user_version`-миграции; таблицы WP-09: `outbox(seq AUTOINCREMENT, event)`,
   `idempotency(key, result)`, `deadlines(id, at_ms)`, `effects(id, key, dedupe, payload, attempts, next_at_ms)`.
   Таблицы прогонов/попыток и т. п. добавляют их пакеты (WP-14+), не заранее (критерий 23).
3. `core.rs` — единственный писатель: задача владеет `Connection`, читает входную очередь (mpsc). На сообщение —
   одна транзакция: проверка ключа идемпотентности → `Handler::handle(&mut Tx, msg)` → события в outbox, эффекты в
   `effects`, дедлайны → commit → ответ вызывающему → разбудить исполнитель эффектов. Дедлайны: цикл ждёт
   `min(at)` через `sleep_until` в `select!` с очередью; срабатывание — сообщение в той же транзакционной модели.
4. `effects.rs` — исполнитель эффектов после фиксации: сериализация на ключ, дедупликация `(key, dedupe)`,
   backoff 500 мс → 5 мин (×2), итог — сообщением в ядро (удаление/перенос в транзакции).
5. Тесты (`tests.rs`, без модели): повтор сообщения с тем же ключом не дублирует эффект; эффект не исполняется до
   фиксации (откат транзакции = эффекта нет); дедлайн срабатывает по управляемым часам без опроса; backoff и
   сериализация по ключу; seq монотонен и переживает переоткрытие БД.

Если не влезет в цикл — шаги 1–3 с тестами коммитятся отдельно, 4 — следующим циклом.
