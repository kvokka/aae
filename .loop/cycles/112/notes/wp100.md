# WP-100 — инструменты ручного восстановления: аудит

Итог: ядро и фронт ничего не добавили — всё нужное уже было. Добавлены тесты, гайд и ссылки.

## Аудит
- Увидеть: `aae run show` (core `Reader::run`) уже отдаёт `class`, `reason`, `bead`, `workdir` и `attempts[]` с
  `kind`, `failure_kind`, `session` каждой попытки (последние 20 = потолок попыток, т.е. все). `aae run list --state
  failed --json` отдаёт тот же вид на каждый прогон. Фильтр по виду отказа не нужен. Текстовый `run list` класса не
  показывает (id, state, place, formula, created_at) — не менял, путь list → show.
- S1: флаг называется `--continue-from` (не `--continue`). Был тест продолжения прогона, упавшего hollow_done
  (`runs::a_run_continues_the_session_of_a_finished_run_only_when_asked`); на прогоне, упавшем на попытке
  (harness_crash), с тем же bead — не было. Добавлен.
- S2: был `beads::failed_runs_release_the_bead_and_the_third_closes_its_gate_until_the_operator_opens_it`. Добавлена
  проверка, что новая попытка — `new_session` с другой сессией.
- S3: без кода ядра. Шаблон промпта принадлежит агенту и проверяется против всех формул агента; отсутствующий
  необязательный вход в шаблоне — ошибка прогона. Поэтому записка = отдельный агент + формула с обязательным входом
  `note`. Код ядра не нужен.
- S4: отмена живого прогона уже покрыта `beads::a_cancelled_run_releases_its_bead_without_counting_a_failure`. Для
  упавшего: bead уже отпущен (open, без assignee), cancel отклоняется; бросить = `aae gate close bead:<p>/<id>`.
