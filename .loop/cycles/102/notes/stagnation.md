## B. Обяз. 1: вход `task` у шага `formula`

**Рекомендация — вариант (а), не заглушка.** Обоснование по [Р]:

- §9.1 [Р]: входы наследуются без исключений, «любой можно задать явно». Заглушка оставляет оба отступления в дереве;
  пометка «31: [Р]-часть ждёт владельца» висела бы до `complete`, а владельца в цикле нет.
- §10.3 [Р]: «у бида не более одного живого прогона-владельца», claim и закрытие — у владельца. Совместимо с §9.1
  только одно чтение: ребёнок работает над бидом родителя, не владея им. Передача владения ребёнку закрыла бы бид
  родителя посреди его формулы.
- §10.3 [Р] «цепочки формул над одним бидом нет» — о прогонах-владельцах подряд; шаг `formula` — часть одного прогона
  (решение 102). Это [Д]-толкование, в журнал.
- Заглушка неполна: `{{ run.bead }}` и `{{ bead.id }}` её обходят. Правило (а) стоит в `create` и ловит всё.
- Размер тот же: (а) — около +30/−15 строк ядра.

### План правки

1. `run/formula_step.rs`, новая `lent(tx, parent: Option<&str>, bead: Option<&str>) -> Result<Option<String>, Error>`:
   `SELECT bead_data FROM runs WHERE id = ?1 AND bead = ?2 AND step_kind = 'formula'`. Без сверки `beads.owner`,
   чтобы работала вложенность: ребёнок может одолжить дальше.
2. `run/queue.rs::create`: `let lent = if direct { None } else { Self::lent(...)? };` — `own_bead` только при
   `lent.is_none()`; в `INSERT` добавить столбец `bead_data` = `lent`. Остальное уже работает без правок:
   - `machine.rs::prepare` при заполненном `bead_data` claim не просит;
   - `beads.rs::let_go_bead` у не-владельца уходит в раннюю ветку: ни `close`, ни `release`, ни счётчика провалов;
   - `drain.rs::created` подменяет `inputs.task` родителя на id бида, так что текстовая задача наследуется как id.
3. `run/render.rs`, ветка `StepKind::Formula`: убрать `.filter(... != InputType::Task)`, поправить комментарий,
   убрать лишний импорт. `config/check.rs::step_inputs`: `inherited = parent.get(k).is_some_and(|i| i.required)`,
   условие без `Task`, поправить rustdoc.
4. Жел. 2, класс: оба вызова `self.step_failed(...)` в `start_formula` заменить на
   `self.terminal(tx, row, "failed", Some("infrastructure"), &why)`, `fn step_failed` удалить.
   - contracts 6.2: `agent` — «финишер сказал `fail`», здесь финишера нет; инв. 13: провал не от работы формулы —
     `infrastructure`. Прецеденты: `drain.rs:38`, `drain.rs:87`, `repeat.rs:47`.
   - Следствие: отвергнутый старт не повторяется по `max_attempts` (отказ детерминирован, [Д] §9.1 «сбой
     инфраструктуры его не расходует»).
   - Там же: `Ok(reply) if reply["run"].is_null()` → тот же `terminal` с причиной `nothing_ready`. Сейчас `task =
     { next_ready = true }` на шаге без готового бида оставляет родителя ждать ребёнка, которого нет, до таймаута
     24 ч. Выведено чтением, не запускал.
5. Дыра, которую открывает (а): родитель упал в шаге (потолок попыток после `runaway_turn`), ребёнок жив и работает
   над уже отпущенным бидом. `formula_step.rs`: `end_child(tx, &row)` — при `step_kind == "formula"` живого
