## Обязательно до продолжения
1. **Загрузчик принимает `where`/`inputs` по `run.*`, которые в рантайме никогда не совпадут.** `schema.rs:115`
   (и все `run.*`-события с `("run", RUN)` в данных) объявляет путь `run.formula`, `run.state`, … существующим, и
   `config::load` такой триггер пропускает. Но `template::event_view` (`template.rs:46`) раскладывает поля
   конверта и `data` в один уровень, а `serde_json::Map` без `preserve_order` обходится по ключам: `data` раньше
   `run`, поэтому строковый `run` конверта затирает `RunView` из данных. Проверено отдельной программой поверх
   `aae-core`: для конверта `run.passed` с `data.run = {id, formula}` — `view.run = "r1"`,
   `Filter{"run.formula" = "implement"}.matches(view) = false`. То есть естественный триггер «после прохода формулы X
   запусти Y» (`on = "run.passed"`, `where = { "run.formula" = "X" }`) загружается без ошибки и молча никогда не
   срабатывает — против contracts 2.1 («путь, которого нет в нагрузке, — ошибка загрузки») и §5.4 (молчаливых
   отказов нет). Корень — в контракте: contracts 1.2 утверждает «payload keys never reuse envelope names», а 1.3
   кладёт `run: RunView` в данные при `run` в конверте. Решить в контракте (например, в представлении ключ данных
   побеждает ключ конверта, а `run.id` — тот же идентификатор; или переименовать одно из полей), поправить
   `event_view` и/или `schema.rs`, записать РЕШЕНИЕ в журнал. Проверка: тест, который строит конверт так же, как
   `journal::envelope`, прогоняет через `event_view` и `Filter`, загруженный из TOML-триггера на `run.passed` с
   `where` по `run.formula`, — и он совпадает (или загрузка такой триггер отвергает). Дёшево; сделать до WP-14/17.

## Желательно
1. **Переопределения оркестратора не проверяются при загрузке.** `load.rs:33` — ключи `[overrides.<agent>]`
   оркестратора не разрешаются ни против одного проекта (у проекта и рига — разрешаются, `check.rs:78`). Опечатка в
   имени агента, как и неоднозначное имя (записано кодером как известное ограничение), молча не применяется
   (`assemble.rs:204`). Проверить при загрузке: ключ должен разрешаться хотя бы в одном проекте и нигде не быть
   неоднозначным.
2. Таймаут хуков: contracts 3.1 — потолок 300 с; `load.rs:107` (exec-хук плагина) и `load.rs:141` (хук харнесса)
   принимают любой. Либо ошибка загрузки, либо явное усечение с записью в контракт — до WP-15.
3. `items.rs:39`: `prompt.md` по умолчанию читается через `.ok()` — любая ошибка чтения, кроме «нет файла»
   (права, не UTF-8), молча даёт агента без промпта роли. Отличать `NotFound` от остального.
4. `journal.rs:181–182`: у `last_seq` осталась старая первая строка rustdoc, теперь неверная («the last line»);
   удалить.
5. `load.rs:238`: сравнение `min_aae` по `Vec<u64>` — версия с суффиксом (`0.2.0-rc.1`) у пака даёт «needs aae …»,
   а если сам `aae` станет пре-релизом, любой пак с `min_aae` перестанет грузиться. Мелочь, но поведение стоит
   записать в `docs/design/config.md` или разобрать semver-часть.
6. План цикла в `.loop/cycles/07/notes/` не написан (каталог пуст) — ревью 06 просило короткий план перед WP-11.
   На результат не повлияло; для M-пакетов держать.
7. Прошлые желательные: ревью 06 п. 2–5 закрыты кодом и тестами (`cancelling_an_idle_session_ends_no_turn`,
   `a_damaged_last_line_does_not_make_the_journal_repeat_lines`, `not_scalar` в тестах шаблона, строка `failure` в
