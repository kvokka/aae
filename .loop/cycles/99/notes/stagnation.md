## 3. Процесс для кодера
1. `coder.md` дописывается после каждого коммита; незакоммиченное вне `.loop` — в «Начато и не закончено».
2. Закрытие цикла начинается не позже 200k контекста: последний коммит в `crates/` → READINESS → `checks NN` →
   отчёт. `git status --short` вне `.loop` пуст. Без `checks.md` с RESULT pass статус `done` не ставится.
3. Правка `scripts/*.sh` — сразу его самопроверка и `mise run ci`. [Д] — в журнал вместе с коммитом, который его
   вводит. Фоновые процессы гасить до отчёта (в цикле 98 `loopctl` добивал три pid).
4. Мутации по своему диффу до отчёта (helper, как в цикле 97). Обязательный набор: каждая ветка `match` по исходу
   (таймаут, сигнал, сбой запуска, потеря) → «прошёл», каждый новый дедлайн → `Ok(())`: все 4 выжившие — такие.
5. Фрагмент TOML в `docs/guide`, тронутый в цикле, вставляется во временный проект и проходит `aae config check`.
6. Сообщение «Застой» до цикла 103 ожидаемо: expert по нему не звать, ссылаться на этот файл (~30k контекста на
   цикл). Предложение по харнессу записать в журнал: считать застой по длине `OPEN`, а не по `SCORE`.
