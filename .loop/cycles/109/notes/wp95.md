# WP-95 · событие `run.permission_denied` — сводка subcoder

## Сделано

- `aae-contract/src/driver.rs`: новый вариант `Normalized::PermissionDenied { tool, tool_use_id: Option, input: Value,
  reason: Option }` — наблюдательный, ничего не ждёт.
- `aae-core/src/run/events.rs`: ядро публикует `run.permission_denied` с `{run, tool, tool_use_id, input, reason}`
  в любом живом состоянии попытки (`starting`/`running`; решение 61 — ничего не терять), в `running` ещё и взводит
  silence как прочая активность. Хуки — без нового кода: это наблюдаемое событие журнала, как `run.retrying`.
- `aae-contract/src/config/schema.rs`: тип и ключи данных (`input` — `Any`), чтобы фильтры `where`/шаблоны их знали.
- claude (`aae-claude/src/stream.rs`): `system/permission_denied` и `result.permission_denials[]` → одно событие на
  `tool_use_id` за ход (множество `denied` чистится на `result`, т.е. без утечки). `reason` = `decision_reason_type`
  (есть только в system-сообщении), `input` = `tool_input` (есть только в `result`). Без `tool_use_id` — событие как есть.
- codex (`aae-codex/src/stream.rs`): каждый серверный запрос треда (адаптер отказывает всем, `rpc::refusal`) →
  `PermissionDenied { tool: <method>, tool_use_id: params.itemId, input: params, reason: params.reason }`.
  Запрос без `threadId` события не даёт (как и прочие сообщения без треда).
- Документы: contracts §1.3 (строка таблицы), §4.3 (строка + фраза про «ничего не теряется»), §4.6 claude (сигналы,
  правило дедупликации, источники форматов) и codex (refusal → `permission_denied`); config.md «Permissions».
  `docs/api/openapi.json` типы событий не перечисляет — не тронут.
- `aae run watch` (`aae-front/src/api/live.rs`): фильтр только по `run`, по типу нет — событие видно без правок.

## Решения и расхождения с пакетом

- Формат `system/permission_denied` вживую не наблюдался. Взят из кода установленного claude 2.1.326 (`emitPermissionDenied`):
  `{type:"system", subtype:"permission_denied", tool_name, tool_use_id, agent_id, decision_reason_type,
  decision_reason_code, decision_reason, message}` — `tool_use_id` в нём есть, поэтому ключ дедупликации общий.
  `result.permission_denials` в 2.1.326 собирается заново в начале каждого хода (`N=[]` на `turn start`) — отсюда
  сброс множества на `result`. Пример `permission_denials` — `experiments/01-claude-protocol/logs/permission.ndjson` (2.1.322).
- Цена правила «первый пришедший»: отказ, о котором сначала пришёл system-вариант, идёт с `input: null`, а
  отказ только из `result` — с `reason: null`. Слияние двух источников потребовало бы держать событие до конца хода.
- codex: событие даёт любой отклонённый серверный запрос треда (не только approvals), т.к. отказ адаптера одинаков.
