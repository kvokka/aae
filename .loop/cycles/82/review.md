1. **Проверка `format` демо 2 на деле ничего не проверяет.** Это [Р] §15 «Демо 2»: «Проверка скриптом: форматирование
   (`rumdl`)… что не смог — уходит замечаниями».
   - Где: `demos/2-multirepo-qa/pack/formulas/deliver.toml`, шаг `format`.
   - Причина: `rumdl check --fix <rig>` по умолчанию уважает `.gitignore`. Риги `frontend/` и `backend/` лежат внутри
     git-репозитория пользователя, а `.gitignore` демо исключает `/frontend/*` и `/backend/*`. rumdl отбрасывает все
     файлы, пишет «No markdown files left to check: 1 file found was filtered out… pass --respect-gitignore=false» и
     выходит с 0. Проверка зелёная всегда, если только агент сам не сделал `git init` в риге. Промпт `implement.md`
     этого не просит, адаптеры тоже не делают.
   - Проверено вживую: копия демо в git-репозитории в `/tmp`, демон на `root/config.toml`, `project list` отдаёт
     абсолютные пути ригов. Конвейер шага в точности: `frontend/README.md` с хвостовыми пробелами и битой ссылкой
     (MD052) не исправлен, а `exit=0`. Тот же файл после `git init` в риге даёт `exit=1` и замечание.
   - Результат автора от этого не ложный: `frontend-example/` и `backend-example/` проходят `rumdl check` чисто, и
     вне репозитория тоже. Но у пользователя проверка пустая. Строка acceptance «a rumdl check… send the work back» и
     README демо обещают то, чего нет.
   - Как закрыть:
     - явно не уважать чужой `.gitignore`: `--respect-gitignore=false` и, например, `--exclude node_modules`, если
       кодеры ставят пакеты; либо перечислять файлы рига;
     - тест без модели: команда шага `format` на риге внутри git-репозитория с игнором правит исправимое и падает
       с замечанием на неисправимом. Мутация «убрать флаг» должна его краснить;
