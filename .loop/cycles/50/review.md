   - Последствия:
     - рестарт идёт на том же порту, поэтому пока чужой процесс держит порт, сервис крутится в рестартах с бэкоффом;
     - при здоровье по умолчанию («порт принимает соединения») проверка проходит по **чужому** слушателю. Сессии тогда
       шлют ему `Authorization: Bearer` с токеном сервиса. Это противоречит §11.4 «loopback с токеном».
   - Нужно хотя бы одно из двух:
     - до первого `service.ready` при сбое старта брать новый порт (предложение кодера);
     - передавать сервису уже открытый сокет.
   - Плюс тест: порт занят посторонним слушателем до старта сервиса → сервис стартует на другом порту, сессии
     получают новый URL, токен чужому не уходит.
   - Проверка: мутация «рестарт всегда на старом порту» краснит тест.
