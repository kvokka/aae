# Расследование: headless claude, метка ENTRYPOINT, переключатели трафика и кэш

2026-11-18…19, вне цикла, по запросу владельца (сессия claude с субагентами). claude 2.1.326–2.1.327, аккаунт
Max 20x. Повод: переезд разработки loop-manager со своего лупа на Claude Code (интерактивный TUI) на сам
loop-manager, а loop-manager запускает claude только как `claude -p`. В anthropics/claude-code#97074 сообщество
мерит, что `-p` (метка `sdk-cli`) расходует квоту подписки в 1,8–2,5 раза быстрее TUI.

Сырые логи (транскрипты stream-json, тела запросов с системным промптом claude, пути машины) — вне репозитория.

## Выводы

1. **Метка.** `CLAUDE_CODE_ENTRYPOINT` уходит в каждый запрос (`x-anthropic-billing-header: cc_entrypoint=…` и
   User-Agent). У `-p` по умолчанию `sdk-cli`, у TUI `cli`; `cli` в `-p` claude переписывает обратно в `sdk-cli`,
   любое другое значение проходит. Квотный эффект метки нами **не подтверждён и не опровергнут**: у аккаунта нет
   5-часового окна, а недельный счётчик стоит $10–20 за пункт. В ветке #97074 эффект есть и без кэша (1,32× при
   `DISABLE_PROMPT_CACHING=1`), с кэшем меньше (1,14×) — похоже, надбавка ложится на свежий вход, а не на чтение
   кэша (гипотеза).
2. **Скрытый запрос на имя сессии.** С любой меткой, кроме `sdk-cli`, claude один раз на сессию шлёт на haiku запрос
   «придумай имя сессии» со всем первым промптом, без кэша (на основной модели — только за прокси в
   `ANTHROPIC_BASE_URL`). Имя пишется только в транскрипт. `total_cost_usd` его учитывает не всегда.
   Выключается `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1`.
3. **Цена на проводе.** Под нагрузкой (Sonnet, ~$0,7 за сессию) ни метка, ни переключатели не выходят за шум
   (±$0,02–0,04 за сессию от разных путей чтения модели). Систематически: заметка «Scratchpad directory» у
   нестандартной метки ≈ $0,002 за сессию, имя сессии ≈ $0,0001. Поведение и результат во всех вариантах одинаковы.
4. **`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`** — не для loop-manager:
   - выключает серверные флаги: другой вариант системного промпта, нет инструмента `advisor`, включается
     обратный отсчёт токенов, сессия выпадает из экспериментов, кэш побочных вызовов — 5 мин;
   - выключает телеметрию и отчёты об ошибках Anthropic (Datadog: класс ошибки, маскированное сообщение, стек,
     теги; без промптов); свой OTel (`CLAUDE_CODE_ENABLE_TELEMETRY` + `OTEL_*`) остаётся;
   - выключает `/api/oauth/usage` и прочий REST; логин и обновление токена работают;
   - проба лимита (`max_tokens:1`) есть только при `CLAUDE_CODE_RETRY_WATCHDOG`; без неё `-p` при исчерпании лимита
     сразу выходит с ошибкой, и ждёт loop-manager (гейт аккаунта).
5. **Кэш.** Время жизни выбирается по источнику запроса, метка его не читает. Подписка: основной поток (TUI и `-p`)
   — 1 ч, субагенты любой глубины — 5 мин; API-ключ или overage — 5 мин. Ручки: `CLAUDE_CODE_PROMPT_CACHE_TTL` /
   `promptCacheTtl` (основной поток), `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` / `subagentPromptCacheTtl` (все
   субагенты), `cacheTtl` в определении агента (перебивается двумя предыдущими). Кэш истекает по паузе между двумя
   запросами потока: 1 ч нужен тому, кто ждёт (основной поток, раздающий работу субагентам, или субагент с долгой
   сборкой). По транскрипту этой сессии: основной поток на 5 мин стоил бы ≈ $24 вместо $10 (15 пауз > 5 мин).
6. **Прогрев кэша** (`POST /v1/messages/cache_touch`, бета `cache-keepalive-2026-09-03`) — только TUI, только
   основной поток, только 1 ч подписки, только при серверном флаге (у аккаунта выключен). В `-p` и для субагентов
   недоступен, настроек нет.

## Как это настраивается в loop-manager (на 2026-11-19)

- Кэш **на сессию агента** — уже сейчас, без кода: `native.claude.promptCacheTtl` и
  `native.claude.subagentPromptCacheTtl` (или `env.CLAUDE_CODE_PROMPT_CACHE_TTL` и
  `env.CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`) на любом слое: агент, шаг формулы, риг, проект.
- Кэш **на отдельного субагента** — нет: `env` и `native` цели субагента до него не доходят (config.md,
  «Subagents»), а в `--agents` адаптер кладёт только описание, промпт, модель, effort, MCP и хуки, без `cacheTtl`.
- Дослать запрос в сессию шага перед его концом — хук аддона на `run.finishing` с решением `remark` (та же сессия,
  та же попытка; считается в потолок 10 замечаний) или check-скрипт шага (`step_check_script_path`, повтор шага по
  `max_attempts`). Дослать в сессию более раннего шага из более позднего — нельзя: у каждого ai-шага своя сессия;
  `continue_from` есть только у нового прогона и продолжает последнюю сессию прошлого.
