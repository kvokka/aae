### 3. Конфиг принимает неизвестное и бессмысленное (правило «неизвестное — ошибка» выполнено не везде)

- **класс**: недоделка · **важность**: средняя (в сумме; каждый пункт по отдельности — низкая)
- **требование**: `docs/design/config.md:6-7` «Unknown keys are an error in every file»; правило владельца «без
  заглушек, конфиг отвергает неизвестное»; первый аудит Г (молча игнорируемые ключи).
- **факт** (каждый пункт проверен `aae config check` — выход без ошибок):
  1. **Неизвестное имя харнесса.** `[harness.cluade] model = "x"` принимается (`crates/aae/src/harness.rs:78`
     проверяет только лишние ключи, не имя). Агент с `harness = "cluade"` проходит загрузку
     (`config/items.rs:46`) и падает уже прогоном: `failed{infrastructure}` «no driver for harness»
     (`run/machine.rs:113-116`).
  2. **Ключи MCP в неверном сочетании молча игнорируются** (`config/files.rs:57` `well_formed` смотрит только на
     `command`/`url`): `mcp.web = { url = "…", env = {…}, scope = "session" }` — `env` и `scope` у HTTP-сервера не
     читает никто (`run/services.rs:42-49` пропускает запись без `command`); `mcp.loc = { command = […],
     headers = {…} }` — `headers` у stdio-сервера отбрасываются (`aae-claude/src/part.rs:141`,
     `aae-codex/src/part.rs:146`).
  3. **Событие хука харнесса не проверяется**: `hooks.h = { event = "PreTolUse", … }` принимается и уходит в
     `--settings` как есть (`aae-claude/src/part.rs:104-128`) — опечатка даёт хук, который никогда не сработает.
  4. **Параметры `default-policy` без диапазонов** (`aae-plugins/src/policy.rs:14-41`, все `i64`/`usize`):
     `backoff_cap_s = -5`, `crash_loop = 0` принимаются; при `crash_loop = 0` условие
     `crashes.count() >= p.crash_loop` (`policy.rs:156`) истинно всегда — любой краш закрывает ворота агента.
  5. **Переменные рига затеняют встроенные поля**: `vars = { path = "…", name = "…" }` принимается, и
     `{{ rig.path }}` в шаблоне молча становится переменной (`run/render.rs:38-41`).
  6. **`formulas/<подкаталог>/*.toml` молча не загружается** (`config/load.rs:346-349`: берутся только файлы
     `.toml` верхнего уровня) — пункт первого аудита Г, не закрыт; то же для не-каталогов в `agents/`.
  7. `permission_mode = "garbage"`, `effort = "ultra-mega"` принимаются (значения «родные» для харнесса — это
     задокументировано, но `config check` о них ничего не скажет; ошибка всплывёт сбоем старта сессии).
  8. `version` плагина и пака — любая строка (`"not-a-version"` принимается); используется только в списках.
- **что сделать** (S–M): 1 — ошибка «no adapter for harness» в `harness::load`; 2 — ошибки сочетаний в
  `Loader::settings`; 3 — список событий диалекта Claude в загрузчике (или у адаптера, как `options_error`);
  4 — `u32`/проверка `>= 1` и `>= 0`; 5 — ошибка на `name`/`path` в `vars`; 6 — либо обход подкаталогов, либо
  ошибка «формула в подкаталоге».

### 4. `${AAE_PLUGIN_DIR}` подставляется не везде; «родные части харнесса» плагину доставить нечем

- **класс**: недоделка · **важность**: средняя
- **где**: `crates/aae-core/src/config/load.rs:155-162`.
- **требование**: §11.2 — плагин добавляет агенту «переменные окружения, … MCP-серверы, … родные для харнесса
  части (например, каталог плагина Claude Code)».
- **факт**: в `[agent]` плагина подстановка делается только в `hooks.*.command` и `mcp.*.command`. В `env`
  агента, в `mcp.*.env` и в `native.<harness>` плейсхолдер остаётся буквальным (у `[[service]]` того же плагина
  подставляется и в `env`, и в `health.command` — несимметрично). Общий stdio-MCP за мостом стартует в `/`
  (`run/service_proc.rs:106`), то есть относительный путь тоже не спасает: серверу плагина нельзя передать свой
  каталог данных через окружение. Каталог плагина Claude Code (`--plugin-dir`) плагин aae передать не может вовсе:
  `native.claude` — только ключи `--settings`, а `--plugin-dir` адаптер занимает под skills
  (`aae-claude/src/part.rs:184-186`).
- **как проверено**: `plugin.toml` с `[agent] env = { MAIL_HOME = "${AAE_PLUGIN_DIR}/data" }` и
  `mcp.m = { command = ["${AAE_PLUGIN_DIR}/bin/m"], env = { X = "${AAE_PLUGIN_DIR}/x" } }`; `aae config explain`
  печатает `env.MAIL_HOME = "${AAE_PLUGIN_DIR}/data"` и `"env":{"X":"${AAE_PLUGIN_DIR}/x"}` при подставленном
  `command`.
- **что сделать** (S): подстановка в `env`, `mcp.*.env` и строковых значениях `native` вклада плагина; про каталог
  плагина Claude Code — либо ключ вклада, либо строка в `plugin.md` «не поддерживается» и запись в журнал как [Д].

### 6. `br`: явного пути в конфиге нет, `mise which` выполняется в cwd демона, один бинарник на все проекты

- **класс**: отход от запроса (допущение [Д] §6.5 выполнено наполовину; пункт первого аудита Г не закрыт) ·
  **важность**: низкая–средняя
- **где**: `crates/aae/src/daemon.rs:113` (`binary("br", None)`), `crates/aae/src/harness.rs:18-30`,
  `crates/aae/src/doctor.rs:65`.
- **требование**: §6.5 — «демон разрешает бинарники харнессов **и `br`** через mise… Запасной путь для машины
  без mise — явный путь к бинарнику в конфиге»; §10.2 — br закреплён в `mise.toml` проекта.
- **факт**: для харнессов ключ `binary` есть, для br — нет: `explicit` всегда `None`, остаётся mise, затем голое

  закреплённый в `mise.toml` проекта, под systemd/launchd не найдётся, и все проекты получают один и тот же br

- **что сделать** (S): ключ пути br в конфиге оркестратора (или проекта) и `mise which` с `current_dir(project.root)`

### 7. Закрепление git-источника проверяется только именем каталога

- **что сделать** (S): в `aae fetch` — проверка чистоты существующего checkout при «kept»; в `doctor` — сверка

### 8. Встроенный `worktree`: таймаут 30 с не настраивается, git по таймауту не убивается

- **требование**: §11.3 «у хука есть таймаут» (у внешних — SIGTERM/SIGKILL группе); решение п. 11 — worktree

- **как проверено**: чтение кода; вживую на большом репозитории не воспроизводилось (сам сценарий — гипотеза,
  механика — факт).
- **что сделать** (S): таймаут встроенного хука на создание — потолок 300 с; git запускать через `process::run`
