### 2.3 (е) «Gas City поверх br» — насколько рабочий путь

- Есть: `[beads] provider = "exec:/path/gc-beads-br"` (`docs/reference/exec-beads-provider.md:33-35`), адаптер
  `contrib/beads-scripts/gc-beads-br` (353 строки bash + jq), conformance `internal/beads/exec/br_test.go`. **[П]**
- Тест — `//go:build integration` и `t.Skip("br not available")` (`br_test.go:1,17-19`); в `.github/workflows` установка `br`
  не найдена (только path-фильтр в `container-scan.yml`) → в CI адаптер, по всей видимости, не исполняется **[В]**.
  Последняя содержательная правка скрипта — 2026-08-03.
- Metadata кодируется в labels `metahex:<hex>:<hex>` (`gc-beads-br:14-15,53-60`); у br лимит 64 labels на бид (отчёт 11), а у
  session-бида в среднем 60, максимум 83 metadata-ключа (отчёт 06) → сессии на br не поместятся **[В]**. Обход — инфра-классы
  на `sqlite-beads`, work на br; на практике эту комбинацию не проверял **[НП]**.
- «Batch and transaction operations are not atomic» (`exec-beads-provider.md:175`); каждая операция — новый процесс
  bash+jq+br с таймаутом 30 с; conditional writes на exec-сторе работают как `off` (`config.md:302`).
- **`gc bd` на не-bd провайдере отказывает**: «gc bd: only supported for bd-backed beads providers» (`cmd/gc/cmd_bd.go:676-677`).
  Work query по умолчанию — shell `bd ready`/`gc ready` (`internal/config/workquery.go:57-58`). Все промпты и скрипты паков
  (`gc bd show` 41, `comments` 25, `update` 11 в `SV/*.md|*.toml`; ~110 вызовов в Python) перестают работать **[П: grep]/[В]**.
- Вердикт: статус «contrib / experimental», путь требует переписать паки под `br` напрямую и spike 1–2 дня в лаб-городе,

### 4.2 Минимальная система (оценка 1,5–2,5 тыс. строк Python) **[В]**

- **Очередь**: одна БД `br` на город (эпик над бидами разных ригов иначе невозможен — отчёт 11), риг и роль — labels
  `rig:<name>`, `role:<name>`. Панель — `bv`. Канонический путь БД через env, агентам `.beads/` не коммитить.
- **Диспетчер** (один процесс под pitchfork — он у владельца уже есть; `systemctl --user` на этой VM `offline` **[П]**):
  цикл «`br ready --json` (26 мс) → `br update --claim` (атомарен, отчёт 11) → `git worktree add` → запуск харнесса роли в
  отдельной process group (`setsid`) с `cwd` = worktree → ждать exit → finisher роли (скрипт: lint/test/проверка артефакта)
  → `br close` либо reopen с `attempt:N`, после N — defer + письмо». Параллелизм — семафор на роль и на (роль, риг).
- **Состояние диспетчера** — одна SQLite-таблица `run(bead, role, pid, session_id, attempt, started, last_event, pause_until)`;
  в трекер служебное не пишется.
- **«Формула»** — TOML-шаблон, раскрываемый в «эпик + дети + `blocks` + `role:`» (150–250 строк). Гейт — бид с
  `gate:human`, который диспетчер не берёт; человек закрывает в `bv`/`br close`.
- **Liveness и квоты**: exit code + mtime последнего события stream-json; stall → SIGTERM группе → reopen;
  `rate_limit_event.resetsAt` → `pause_until` для роли. Состояния «ждёт лимита / ждёт логина» — явные строки в `run`.
- **Ордера**: шесть ордеров владельца — все `cooldown + exec` → таймеры pitchfork/cron напрямую.
- **Оператор**: обычная интерактивная сессия `claude` в каталоге города; attach к завершённой рабочей — `claude --resume <id>`.

## 8. Честное предупреждение: что говорит собственный аудит владельца

Факты из `PACKS/docs/metropolis-audit-2026-10-29.md` **[П]**:
- 30,7 тыс. строк пака + 41,8 тыс. строк тестов, 178 коммитов за 8 дней (`:25-28`); живьём — 3 эпика (`:41`).
- ~8 тыс. строк (четверть) лишние (`:176`); 0 живых использований у cross-rig вопросов, decision-гейтов, `land=merge`, in-step retry (`:42-45`).
- «Most of the machinery was built for, and verified only against, lab scenarios the same agents wrote» (`:51`).
- 13 строк таблицы «gc has → metropolis built instead» (`:180-194`): `[steps.retry]`, `gc worktree`, `idle_timeout`,
  event-ордера, `escalate.sh`, overlay на агента — всё это в gc было.
- README и комментарии содержали ложные утверждения (`:13-14`).

Что это значит для нового большого проекта **[В]**:
1. **Скорость генерации — источник проблемы, а не решение.** 4 тыс. строк в день агентами — тот же механизм, которым Gas City
   дошёл до 930 тыс. (81 % коммитов с Claude). Новый оркестратор будут писать те же агенты с теми же привычками.
2. **Неполное знание базы.** Владелец не знал о 13 готовых механизмах gc. При переписывании он не знает о сопоставимом
   числе инвариантов (отчёт 21: 27 классов остаются, 10 новых). Список инвариантов — до первой строки кода.
3. **Лаб вместо жизни.** Город — полигон (48 запусков за 22 дня). Требования к новой системе выведены из той же малой выборки.

Как ограничить (правила владельца из `new-pack-rules.md:15-27`, перенесённые на ядро):
- **Бюджеты, проверяемые CI, а не обещанием:** v0 ≤ 5 тыс. строк, жёсткий потолок 15 тыс.; файл ≤ 300 строк; тесты ≤ 2× кода.
- **«No mechanism without a live incident»** (правило 1): ни ACP-хаба, ни MCP-пула, ни control pane, пока прототип не упёрся в их отсутствие на реальной работе.
- **Одна реализация каждого слоя:** один стор, один транспорт на харнесс, один reconciler; вторую не начинать, пока не удалена первая (урок 15,6 % «миграционного» кода, отчёт 01).
- **Kill-критерии с датой:** через 2 недели новая система не ведёт реальный эпик владельца → стоп, возврат к C1-полному;
  через 4 недели код > 15 тыс. строк или появился второй стор/транспорт → стоп и аудит.
- **Еженедельный «delete review»:** что не исполнилось живьём за неделю — удаляется.
- **Перед каждым новым механизмом** — проверка, нет ли его у вендора (`claude --help`, `codex --help`) и в gc; запись ссылки в коммит.

## 9. Вердикты по гипотезам (вклад этого отчёта)

- **H5 (br+bv вместо bd+Dolt)** — частично. Внутри Gas City замена не работает (п. 2.3); вне его как трекер работы — да (C3).
- **H7 (кода больше нужного)** — подтверждена и со стороны владельца: половину шума ордеров создают его собственные паки.
- **H8 (тики → простои)** — частично. v2 + split сокращают хоп примерно вдвое; пол задаёт холодный старт tmux + харнесса.
  При 199 шагах за 22 дня суммарный простой ~100 минут.
- **H11 (переписать с нуля)** — **не доказана и не опровергнута; решение преждевременно.** Острая боль (токены dog, шум ордеров)
