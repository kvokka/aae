| Исчезает | 69 | 34.5 % | 51 % | ±8.4 |
| Упрощается | 53 | 26.5 % | 39 % | ±8.2 |
| Остаётся | 14 | 7 % | 10 % | ±5.1 |

- Экстраполяция на 1609: ~555 исчезают, ~425 упрощаются, ~115 остаются, ~515 вне темы **[В]**.
- Перекрёстная проверка regex по всем 1609 темам: tmux/TUI 79, Dolt/bd/split/кэш 279, тик/legacy 38 — то есть 24.6 % всех фиксов исчезают уже по
  ключевому слову; «вне темы» 26.7 % **[П]**. Regex занижает «исчезает»: фиксы scope `session`/`reconciler` о кэше, lease и legacy-путях он относит к lifecycle.
- Погрешность шире статистической. Граница «упрощается / остаётся» субъективна: надёжнее читать как «исчезает ~50 %, остаётся в каком-то виде ~50 %».
  Тема коммита не всегда называет причину. Выборка — 4.3 месяца, период активной миграции v2 и split-store (в октябре 550 фиксов против 267–315 в
  июле–сентябре), что завышает долю «исчезает» **[В]**.
- Состав «исчезает» в выборке (69): хранилище — Dolt/bd/split-store/кэш/служебные биды — 50, tmux/TUI 14, тик/legacy/многопроцессность 5 **[П]**. Главный источник исчезающих
  фиксов — хранилище, а не tmux.

## 4. Следствия для дизайна

### 4.1 Обязательные инварианты v0 (раздел C)

1. **Один писатель состояния.** Все мутации state оркестратора делает демон в транзакциях SQLite; CLI и агенты идут через его сокет. Без этого: 042193bad, a7e73d6d4.
2. **Владение с generation.** У бида не более одного живого владельца; владение — строка (bead, session-run id, generation); каждый эффект сессии (закрытие, результат, release) проверяет generation. Без этого: bb9c90d73, f173e5148.
3. **Claim выдаёт оркестратор, не агент.** Шаг назначается в той же транзакции, что и решение его выдать. Без этого: 18a47daec (14 сирот из 14), 3efe0a867 (35 % пустых стартов).
4. **Release только условный** — CAS по (owner, generation). Без этого: 31a8d0b7e, 5139b90c3.
5. **Смерть владельца возвращает работу.** Exit/EOF сессии в одной транзакции переводит её шаги в «к повторной выдаче»; resync ловит пропущенное. Без этого: 7eb0c7045, fa8c704fb.
6. **Подтверждённая смерть до замены.** Новый процесс на тот же шаг или session id стартует только после `wait()` всей группы старого. Без этого: bb9c90d73.
7. **Сессия — process group, убивается целиком;** демон — subreaper. Без этого: e4782ddff, 4b39943a1 (165k зомби), a74e4ca79 (убиты чужие процессы).
8. **Один писатель на session id харнесса.** Prompt/load/resume делает только держатель lease; человек подключается через демона. Без этого: ветка транскрипта (отчёт 14); в Gas City — «ACP provider does not own session» (отчёт 04).
9. **Intent до эффекта.** Start/stop/kill/suspend сначала записываются, потом исполняются; recovery доводит или откатывает. Без этого: 5a10c58da, 4a4ef05a6, ba71e3fb1.
10. **Идемпотентность по (run, step, attempt).** Создание шага, выдача, запись результата и событие повторяемы без дублей. Без этого: 042e965f0 (3 корня на бид), 1b991d75c, 6e441be0a.
11. **Незавершённый ход после рестарта демона не ждёт молча.** Либо `session/load` и явный prompt-продолжение, либо новая attempt; группа старого хода убита заранее. Без этого: 1e9b3be39 и класс 66.
12. **Успех шага — только по durable-результату.** Pass ставит явный outcome агента или check; `end_turn` без outcome = fail. Без этого: `formula-spec-v2.md:1050`, 42b11ccbd, класс 62.
13. **Зависимость открывает только pass; прерывание инфраструктурой — не исход.** Cancel, рестарт и квота дают `transient`/`cancelled`. Без этого: 1928ef6, 2f6959fdd.
14. **У каждого переходного состояния дедлайн и терминальный выход** (starting, draining, cancelling, ожидание permission): по истечении — kill группы и алерт. Без этого: 6becabe41, 67e786ee7.
15. **Watchdog выданного шага.** Дедлайн до первого события и предел тишины по потоку протокола; реакция cancel → fresh → алерт, по разу на эпизод. Без этого: `execution_backstop.go:3-14` (15–85 мин), `metropolis-audit-2026-10-29.md:348`.
16. **Ограниченные рестарты и retry, счётчики durable.** Capacity и квота не считаются крашем; quarantine не укорачивается. Без этого: 9a6040b93, 952b39c32, efe044c37; в Gas City трекер крашей живёт в памяти и сбрасывается рестартом контроллера (`cmd/gc/crash_tracker.go`, по отчёту 03 §2.4в).
17. **Resume с проверкой.** Только при существующем транскрипте; три resume-отказа подряд ⇒ fresh; fresh сохраняет владение шагом. Без этого: 468a4bfc2, 1d496fdb4.
18. **Operator hold сильнее автоматики.** Suspend/kill/close человека — отдельный durable-факт, который читает каждое автоматическое решение. Без этого: fde2b489f, 227ebd6f9.
19. **У worktree один владелец.** Удаляет владелец и только когда коммиты достижимы из refs; живую сессию не перепривязывают к другому cwd. Без этого: bb36f78c9, 1baf214eb, 94eda8f2e.
20. **Событие — повод перечитать; resync обязателен; неоднозначность ⇒ ноль эффектов и громкий сигнал.** Без этого: b02215da7, da84dbfed, 6fbd6bdaa (3 дня при зелёных метриках); `engdocs/architecture/reconciler-v2.md:558` (A12).

### 4.3 Чего не переносить (раздел E)

Механизмы, которые лечат симптомы tmux, Dolt, тиков и многих писателей **[В]**:

- **tmux:** подтверждение submit и восстановление черновика, разбор диалогов, input fence, `StateCache`, вычитание своих нажатий из activity, OSC 7501 relay, маркеры pane.
- **Dolt:** жизненный цикл managed-сервера, compact/GC/backup, поиск порта, `doltorphan`, retry сериализации.
- **Split-store:** `storebinding`, residency, class handles, миграции инфра-бидов.
- **`CachingStore`** и события `cache-reconcile`/`cache-local`, write-fence и watermark'и.
- **Сессия как бид:** session-биды, резервирование имени открытым бидом, канонизация alias, имена слотов pool.
- **Межпроцессная координация:** runtime lease и flock на имя сессии, kill fence, mutation lock. Одному процессу хватает очереди по ключу.
- **Claim со стороны агента:** `gc hook --claim`, claim window, протокол drain-ack. Заменяются выдачей шага и концом хода.
- **Control-биды в трекере** (scope-check, workflow-finalize, retry-eval), spec-sidecar'ы, quarantine control-бидов.
- **Order-tracking биды и sweep-orders:** `orphan-sweep`, `nudge-mail-sweep`, `gate-sweep`, convoy sweep, wisp GC.
- **Бюджеты тика:** `max_wakes_per_tick`, `max_dispatches_per_tick`, `tick_debounce`, poke.
- **Два reconciler'а и rollout-гейты.**
- **Поллер nudge на сессию, quiescence-окно, wait-idle.**
- **Поиск транскрипта по рабочему каталогу.** Оставить только поиск по ключу сессии.

Оговорка: идеи за этими механизмами (fence по инкарнации, условная запись) остаются — как инварианты 2, 4, 8, но внутри одного процесса.

### 4.4 Насколько реален риск и как его снизить (раздел F)

Оценка **[В]**, все числа от ~1095 профильных фиксов за 4.3 месяца:

- **Исчезает ~555.** Риск близок к нулю, если не вернуть причину (кэш над трекером, служебное состояние в `br`, второй процесс-писатель).
- **Упрощается ~425.** Нужен один механизм на класс, но его тоже надо сделать правильно. Допущение: на это уйдёт 20–30 % прежнего объёма, то есть 85–130 фикс-эквивалентов.
- **Остаётся ~115.** Встретятся почти полностью.
- **Итого 200–245 фикс-эквивалентов, ~20 % (15–30 %).** Плюс 10 новых классов без чужого опыта; по ним оценки нет **[НП]**.

Знание не извлекается чтением кода за один проход: 80 из 1609 фиксов прямо названы follow-up, regression или supersedes (нижняя граница, 5 %); 149 ссылаются
на id инцидента; в коммитах за 12 дней названы 44 ревизии контракта v2 при работающем симуляторе **[П]**. Существенная часть этих ревизий — сосуществование legacy и v2 и
внешние писатели, которых в новой системе нет **[В]**.

Как снизить:

1. **Один процесс-писатель и явная таблица переходов** сессии и шага с дедлайном на каждое переходное состояние. Закрывает классы 10, 13, 14 by construction.
2. **Fake-драйвер харнесса с первого дня.** Скриптуемый: ход с задержкой, `end_turn` без результата, ошибка провайдера, exit 75, зависание, обрыв pipe посреди хода, permission-запрос, событие вне хода. В Gas City аналоги — `internal/runtime/acp/testdata/fakeacp`, `internal/runtime/fake.go`, `internal/worker/fake`.
3. **Детерминированный симулятор:** инжектируемые часы, seed, проверка инвариантов 1–20 после каждого шага и при покое. Образец — I1–I24 и корпус 1024 seed.
4. **Fault injection по точкам записи:** `kill -9` демона на каждой границе транзакции и между записью в state и в `br`, затем recovery обязан сойтись. Это прямой тест классов 12, 59, 68.
5. **Property-тесты** на идемпотентность: любая операция, применённая дважды, и любое событие, доставленное дважды или не доставленное, дают то же конечное состояние.
6. **Conformance-набор на драйвер** против настоящего харнесса с prompt «reply OK»: cancel, resume после kill, второй писатель, ошибка провайдера. Запускается при каждом обновлении адаптера (классы 57, 63).
7. **Resync с первого дня,** а не после первого потерянного события.
8. **Каждый отказ действовать пишет причину.** Самые длинные простои Gas City — молчаливые (6fbd6bdaa, bff31d320).

## 5. Открытые вопросы и непроверенное
