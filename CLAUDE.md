# aae — правила для агентов

Greenfield-реализация `aae` на Rust по спеке `docs/init/AAE-SPEC.md`. Работа идёт автономным циклом
coder → reviewer под мастером (`overseer`), без оператора. Протокол цикла — в определениях агентов
`.claude/agents/` и в `scripts/loop/loopctl`.

## Спека и контекст — читать кусками

- Спека — ~1200 строк, ~40k токенов. Оглавление: `grep -n '^##' docs/init/AAE-SPEC.md`; читай нужные секции через
  Read с `offset`/`limit`. Метки: [Р] — решение владельца, не пересматривается; [Д] — допущение, менять только с
  записью в журнал; [НП] — не проверено, сначала опыт.
- Шпаргалки по харнессам и br: `docs/init/aae-context/` (порядок чтения — его `README.md`), каждая 10–20k
  токенов. Лаборатория `docs/init/aae-context/lab/` есть на диске, но не в git (абсолютные пути владельца) —
  в репозиторий её содержимое попадает только после чистки (§19 спеки).
- Отчёты `docs/init/reports/` исполнителю не нужны, кроме точечных ссылок из §19.

## Бюджет контекста

Каждый агент: мягкий предел 300k токенов, жёсткий 420k. На 300k хук просит сворачиваться (довести шаг, закоммитить,
дописать отчёт: сделано / не вышло / начато и не закончено), на 420k агент останавливается принудительно и
родитель получает автоматический дамп из `.loop/handoffs/`. Сжатия контекста у рабочих агентов нет — объём работы
планируется заранее так, чтобы закончить к ~250k.

- Вывод команд всегда обрезан: `cargo build -q --message-format short 2>&1 | head -60`,
  `cargo clippy --all-targets -q --message-format short -- -D warnings 2>&1 | head -60`,
  `cargo nextest run --no-fail-fast --status-level fail --final-status-level fail 2>&1 | tail -80`.
- Grep до Read; Read с offset/limit; не читать `Cargo.lock`, `mise.lock`, `target/`, длинные логи целиком.
- Тяжёлое чтение и прогоны — субагентам; они возвращают выжимку, детали — в файл.

## Версии и инструменты

- Всё — на последних релизных версиях на момент добавления, с закреплением: crate добавляется `cargo add <crate>`
  без версии, `Cargo.lock` в git; инструменты — точные версии в `mise.toml` и `mise.lock` (`mise use <tool>@<x.y.z>`).
  Без причины не обновлять; обновление — отдельным коммитом.
- Тулчейн — `mise.toml`: Rust 1.99.1 (clippy, rustfmt, rust-analyzer, цели linux-musl и apple-darwin под обе
  архитектуры), cargo-nextest, cargo-deny, cargo-machete, tokei (счётчик строк для бюджетов §14), zig и
  cargo-zigbuild для кросс-сборки. Если команда не находится — `mise exec -- <команда>`.
- Внешние бинарники (claude, codex, br) закрепляются в `mise.toml` проекта, как требует спека §13.

## Живые модели в тестах

Контрактные тесты §7.8, опыты §16 и сценарии «запрос» §15 разрешено гонять на настоящих `claude` и `codex`, но
только на самой дешёвой модели (claude — haiku; codex — самая дешёвая доступная) и точечно: перед запуском —
понятно, что проверяется; после — запись в журнал (что, сколько прогонов, итог).

## Журнал `.loop/JOURNAL.md`

Оператора нет, вопросы не задаются в чат. Всё, что нужно владельцу, — находки, вопросы, принятые решения по [Д],
блокеры, нарушения — дописывается в конец журнала, прошлые записи не меняются:

```bash
cat >> .loop/JOURNAL.md <<'EOF'

## 2026-11-12T14:05 · цикл 3 · coder · ВОПРОС|НАХОДКА|РЕШЕНИЕ|БЛОКЕР

Суть в 1–6 строк; ссылка на файл:строку или секцию спеки. Для вопроса — какой вариант принят до ответа владельца.
EOF
```

## Git и харнесс

- Работа в `main`. Коммиты атомарные, понятные. Пуш делает цикл после ревью (`loopctl`); force-push, переписывание
  истории, `--no-verify` запрещены.
- Файлы харнесса — `.claude/`, `scripts/loop/`, `CLAUDE.md` — в цикле не меняются (хук блокирует, `loopctl`
  откатывает). Предложение по харнессу — запись в журнал.
- Репозиторий публичный, MIT: никаких секретов, абсолютных путей машины владельца и содержимого `lab/` без чистки.
